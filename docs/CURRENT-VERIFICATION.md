# Проверка RU-моста и калибровки

Дата: 3 ноября 2026. База изменений: `af909e63292f3a265758ffda355d5e0b99c4f010`; исправленный код сборки отправлен в ветку `ru-custom`, коммит [`4d7a45e64`](https://github.com/m0peterson/xdrip-ru-custom2/commit/4d7a45e64a34c0f5d7c8c78331709c13a892481d).

## Проверяемый сценарий

FreeStyle Libre 2 RU → Juggluco → Patched Libre broadcast → `LibreReceiver` (`Libre2 Patched`) → сохранение / калибровка / график xDrip.

Прямой драйвер Gen2 в проекте отсутствует. Классификация `Libre2Gen2` и подсказка при NFC-сканировании не являются реализацией расшифровки и Bluetooth-аутентификации. Работу конкретной модели RU-сенсора в Juggluco нужно подтвердить отдельно.

## Найденные и исправленные проблемы

1. `bgReadingInsertLibre2` применял `Calibration.lastValid()` даже в `no_calibration`. Теперь все пути моста проверяют разрешение калибровки перед её применением. Переключение не удаляет сохранённые калибровки и не переписывает старую историю.
2. Тренд рассчитывался до сохранения текущего показания. Это противоречило инварианту `find_slope()` и приводило к ошибке при включённых Java assertions. Теперь показание сначала сохраняется; исторические вставки не используют расчёт текущего тренда.
3. Scan/history и минутный поток имели разные пути вставки. Они объединены на glucose-scale обработке в `BgReading.bgReadingInsertLibre2`: без искусственного преобразования в Dexcom raw, с одинаковым режимом калибровки и дедупликацией в рамках активного сенсора.
4. Выборка для сглаживания включала другие серийные номера и не ограничивалась временем входящей точки. Теперь используются только предыдущие точки того же серийного номера; некорректные и будущие относительно точки значения не участвуют в среднем. Повтор сообщения не дублирует входную точку в БД сглаживания.
5. Отсутствующие поля и нечисловые значения могли попасть в обработку минутного сообщения. Добавлена валидация до создания сенсора/записи, а обработка асинхронного broadcast удерживается через `goAsync()` с `finish()`.
6. Часы распознавали Gen2, но продолжали неподходящий NFC-путь. Добавлена остановка с подсказкой использовать телефонный мост. Короткий `patchInfo` больше не вызывает выход за границы массива (телефон и wear).
7. Пользовательское имя настройки калибровки упоминало только OOP2. Теперь RU/EN пояснения называют также мост Libre.
8. Тест переводов искал удалённый в новых AGP каталог `merged-not-compiled-resources`. Список локалей теперь берётся из `app/src/main/res`, а строки проверяются через ресурсы приложения; проверки формата строк сохранены.
9. Сохранён маркер `Libre2 Native`: Wear принимает по нему показания без объекта калибровки. Это проверяется в сценариях первого значения и `no_calibration`, чтобы единый путь вставки не нарушал передачу на часы.
10. Старые документы ссылались на тесты другой ветки и APK другого форка. README и два руководства переписаны; старый отчёт помечен историческим.

## Автоматические проверки

Целевая проверка завершилась успешно при стандартных включённых Java assertions: **22 теста, 0 failures, 0 errors, 0 skipped**.

| Класс | Тестов | Что проверяет |
|---|---:|---|
| `LibreBridgeCalibrationTest` | 10 | Вставка до калибровки, расчёт/отключение поправки, история, дедупликация, меню, реальный ввод калибровки в mg/dL и ммоль/л |
| `LibreReceiverTest` | 8 | Intent минутного потока и scan/history, метаданные смены сенсора, повторный вход, некорректные сообщения, границы сглаживания |
| `LibreGen2Test` | 4 | Семейства Gen2, сохранение EU/Libre3 классификации, короткий patchInfo, пределы смещения |

Команда целевой проверки:

```bash
source /workspace/.setup-xdrip/env.sh
cd /workspace/xdrip-ru-custom2
bash gradlew :app:testFastDevUnitTest \
  --tests '*LibreBridgeCalibrationTest' \
  --tests '*LibreReceiverTest' \
  --tests '*LibreGen2Test' \
  --max-workers=4 --console=plain
```

Первые запуски новых тестов выявили необходимость изоляции существующих статических context/preferences и БД между сценариями; очистка тестовых записей включает SensorSendQueue до удаления сенсоров, чтобы соблюдать внешние ключи. После исправления фикстуры все 22 проверки выполнены заново без ослабления ожиданий.

В тестах используется реальная модель БД через Robolectric, реальные `Calibration.create` и обработчик payload `LibreReceiver.handleIntent`, а не копия формул в тестовом коде. Assertions не отключаются.

Начальная попытка проверки старого кода не дошла до тестов: скачивание `dagger-2.25.4.jar` из Maven Central завершилось тайм-аутом. Артефакт получен из официального Maven Central и сверён с опубликованным SHA-1 `67412d9195a7063fa71944f3a5dc8034757ec822`; после этого повторён запуск. Проверка TLS оставалась включённой. Этот сбой не считается ни провалом тестов продукта, ни успешной baseline-проверкой.

## Что тесты не подтверждают

- Доставку настоящего Android broadcast из установленного Juggluco: тест вызывает тот же синхронный обработчик с построенным по протоколу Intent.
- Реальное чтение сенсора, NFC/Bluetooth, фоновое поведение конкретного Android/OEM, аппаратную точность показаний.
- Звук тревог, Nightscout, AAPS и часы в реальном использовании.
- Подписанный release APK и весь release CI, если отдельно не указан успешный результат этих задач.

История scan-протокола вставляется по полученным точкам без spline-интерполяции. Обычный Patched Libre broadcast Juggluco передаёт текущие значения; наличие history-обработчика не означает автоматическое восстановление всех пропусков. Без метаданных старта нового сенсора может потребоваться вручную сменить локальную сессию xDrip.

Штатный алгоритм калибровки, предел смещения −40…+20 mg/dL и наклон 1 для `LibreReceiver` сохранены. Другие коллекторы, включая Dexcom, не переводились на новый путь.

## Аппаратная приёмка

На телефоне выполните [чек-лист GUIDE.md](GUIDE.md#11-проверка-готовности-на-реальном-телефоне). Обязательно проверьте: приём без калибровки, поправку после ввода значения в выбранных единицах, отключение поправки для новых точек, непрерывную работу с выключенным экраном и новую сессию при замене сенсора.

Источники для инструкции Juggluco: [официальное описание](https://www.juggluco.nl/Juggluco/), [страница загрузок](https://www.juggluco.nl/Juggluco/download.html), [описание glucose broadcasts](https://www.juggluco.nl/Juggluco/glucosebroadcast.html).
